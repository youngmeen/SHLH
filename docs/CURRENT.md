## 1. 현재 단계

- 제목 기반 1차 분류(`audience-match.ts`)가 있다 — 청년/신혼/다자녀/고령자/한부모를 제목에서 읽어 관련/확인/불일치로 나눈다

```text
자산        확인 필요
청약통장    확인 필요  (원문에 청약저축 요건 있음 · 미보유로 입력됨 — 접수 전 가입 가능)
```

## 4. 변경 대상

### 4.1 선행 — 프로필 생년월일 전환 (G8)

- `profile.ts`: `birthDate`(YYYY-MM-DD) 추가. **기존 `age`는 지우지 않는다** — 생년월일이 비어 있으면 fallback으로 쓴다(이미 저장된 프로필이 깨지지 않아야 한다)
- 만 나이 계산 함수. **판정 기준일 = 공고일**(R12·ROADMAP 선행 조건)
- 화면: 나이 입력 → 생년월일 입력(계산된 만 나이를 옆에 표시)

### 4.2 프로필 필드 추가 (Phase 3 구현 대상 조건들)

- `hasSubscriptionAccount`(청약통장 보유) · `subscriptionPaymentCount`(납입 인정 회차)
- `carValue`(자동차 가액, 만원 · 0=없음)
- `residence`(거주지: 서울/수도권/그 외)
- `welfare`(없음/수급자/차상위)

### 4.3 자격 판정 — `app/lib/eligibility.ts` (신규)

- `audience-match.ts`에서 **AudienceType 추출을 분리**하고(제목 → 청년/신혼/…), 기존 `evaluateAudience`는 그것을 쓰도록 정리한다. 같은 기능을 두 곳에 두지 않는다(ROADMAP)
- `evaluateEligibility(profile, notice, 상세 신청자격 텍스트)` → 항목별 `충족/미충족/확인 필요` + 근거 문구
- 상세 텍스트에서 뽑는 것: 연령 범위(`만 19세 이상 39세 이하`), 소득 %(`도시근로자 월평균소득 100%`), 자산·자동차 금액(`3억 6,100만원` → 만원 환산), 청약통장 요구 언급
- 판정 성향(R14): **미충족은 프로필이 명백히 어긋날 때만**(주택 보유, 원문 명시 연령 범위 밖). 정보가 없으면 언제나 `확인 필요`. 청약통장 미보유는 접수 전 가입이 가능하므로 미충족이 아니라 `확인 필요`+안내
- 순수 함수로 둔다 — 화면과 알림(Phase 8의 cron)이 같은 판정을 쓴다

### 4.4 화면 연결

- 상세 패널의 조건 점검 구역을 판정 표로 교체(항목·상태·근거)
- 프로필 대화상자에 새 필드 입력 추가

## 5. 하지 않는 것

- **가구원수별 소득·자산 기준표 구조화** — 기준표는 공고문 PDF에만 있다(S3 미결). PDF 파싱을 결정하기 전에는 원문 % 문구 인용 + `확인 필요`까지만 한다
- 순위(1·2·3순위)별 세분 판정 — 순위 조건도 대부분 PDF에 있다. 상세 텍스트에 있으면 인용만 한다
- 추천·정렬(Phase 7), 알림(Phase 8), 출퇴근(Phase 4)
- SH 게시판 본문 파싱 확장 — 이 단계의 텍스트 판정은 LH 상세(`notice-detail.ts`)가 주는 것까지만

## 6. 검증 방법

- 만 나이: 생일 전날/당일/다음날, 윤년(2월 29일생) 경계
- 옛 프로필(나이 숫자만 저장) 호환: `parseProfile`이 깨지지 않고, 판정은 age fallback으로 돈다
- 연령 텍스트 파싱: 범위/이상만/없음
- R14 고정: 상세 텍스트가 없으면 소득·자산·통장이 전부 `확인 필요`이고, 전체 판정이 `지원 불가`가 되지 않는다
- 주택 보유 → 무주택 항목 미충족, 전체 비추천
- 금액 파싱: `3억 6,100만원` → 36,100 / `3,708만원` → 3,708

## 7. 완료 조건

- `✓` 생년월일 입력 시 만 나이가 공고일 기준으로 계산된다. 기존 저장 프로필도 깨지지 않는다
- `✓` 공고를 열면 연령·무주택·혼인·소득·자산·자동차·거주·세대·청약통장·복지자격 항목이 상태+근거와 함께 보인다
- `✓` 상세 텍스트에서 연령 범위를 읽으면 그 값으로 판정하고 원문을 근거로 인용한다
- `✓` 정보가 없는 항목은 전부 `확인 필요`다. 임의로 `지원 불가` 처리하지 않는다(R14)
- `✓` 위 검증 방법이 회귀 테스트로 고정되고 `npm test`가 통과한다
