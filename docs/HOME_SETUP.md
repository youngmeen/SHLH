# 집 컴퓨터 설치 및 실행

## 목적

다른 컴퓨터에서 이 프로젝트를 안전하게 내려받고 동일한 개발 환경을 만드는 절차입니다.

## 현재 확인 사항

- 필요한 Node.js 버전: `22.13.0` 이상
- 현재 개발 환경 확인 버전: Node.js `26.4.0`, npm `11.17.0`
- 현재 프로젝트에는 Git 원격 저장소가 연결되어 있지 않습니다.
- 실제 공공데이터 인증키는 `.env.local`에 있으며 Git에서 제외됩니다.

## 1. 소스코드 옮기기

권장 방법은 비공개 Git 저장소입니다.

현재 컴퓨터에서 원격 저장소를 만든 뒤 소스를 커밋하고 푸시합니다. 인증키가 들어 있는 `.env.local`은 절대 추가하지 않습니다.

집 컴퓨터에서는 다음과 같이 받습니다.

```bash
git clone <비공개-저장소-주소>
cd lh-sh-housing-planner-site
```

Git을 사용하지 않는다면 프로젝트 폴더를 압축해서 옮길 수 있습니다. 이때 `node_modules`, `dist`, `.wrangler`, `.env.local`은 제외하고 집 컴퓨터에서 다시 생성합니다.

## 2. Node.js 설치

Node.js `22.13.0` 이상을 설치하고 확인합니다.

```bash
node --version
npm --version
```

## 3. 의존성 설치

프로젝트 루트에서 실행합니다.

```bash
npm ci
```

`package-lock.json` 기준으로 동일한 버전을 설치하기 위해 `npm install`보다 `npm ci`를 권장합니다.

## 4. 환경변수 설정

```bash
cp .env.example .env.local
```

`.env.local`을 열어 공공데이터포털에서 발급받은 키를 입력합니다.

```dotenv
MOLIT_MYHOME_API_KEY=실제_인증키
```

- Encoding 또는 Decoding 키를 복사한 그대로 입력합니다.
- 따옴표는 필요하지 않습니다.
- 키를 Git에 커밋하지 않습니다.

## 5. 실행

```bash
npm run dev
```

터미널에 표시되는 Local URL을 브라우저에서 엽니다. 기존 프로세스가 포트를 사용하면 `3001`, `3002`처럼 다른 포트가 선택될 수 있습니다.

## 6. 정상 동작 확인

```bash
npm run lint
npm test
```

화면에서는 다음을 확인합니다.

- 상단에 공식 공고 연결 건수가 표시되는가
- `우선 확인할 공고`가 보이는가
- 공고 선택 후 신청자격·임대조건이 로드되는가
- `.env.local`이 없을 때 오류 메시지가 인증키 값을 노출하지 않는가

## 문제 해결

### 마이홈 API가 403을 반환하는 경우

1. 공공데이터포털 활용신청 승인 상태를 확인합니다.
2. `.env.local`의 변수명이 `MOLIT_MYHOME_API_KEY`인지 확인합니다.
3. 앞뒤 공백이나 잘못된 따옴표를 제거합니다.
4. 개발계정 일일 호출 한도를 확인합니다.

### 포트가 이미 사용 중인 경우

터미널에 새로 표시된 Local URL을 사용하거나 다음처럼 포트를 지정합니다.

```bash
npm run dev -- --port 3001
```

### 상세 공고만 로드되지 않는 경우

LH·SH 원문 사이트가 일시적으로 느리거나 차단했을 수 있습니다. 목록 수집과 상세 추출은 별도 요청이므로 목록은 정상이어도 상세만 실패할 수 있습니다.
