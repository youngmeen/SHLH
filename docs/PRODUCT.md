# 집알림 PRODUCT

## 목표

서울 및 현재 생활권에서 출퇴근 가능한 수도권 지역의 임대주택 공고가 올라오면 내가 직접 모든 공고문을 찾아보고 분석하지 않아도,

- 내가 지원할 수 있는 공고인지
- 공고 안에 내가 살고 싶은 주택이 있는지
- 현재 생활 거점을 기준으로 현실적으로 출퇴근 가능한지
- 있다면 어떤 주택을 우선 확인해야 하는지

빠르게 알 수 있도록 하는 개인용 임대주택 지원 도구를 만든다.

최종 목표는 **당첨될 때까지 새로운 공고를 놓치지 않고 반복해서 지원할 수 있게 하는 것**이다.

## 해결하려는 문제

현재는 LH·SH 등의 공고를 직접 확인하고 공고문과 첨부파일을 읽어야 한다.

하나의 공고에도 여러 지역과 여러 주택이 포함될 수 있어 실제로 내가 지원하고 싶은 주택을 찾는 데 시간이 걸린다.

또한 단순히 서울·경기와 같은 행정구역만으로 주택을 판단하기 어렵다.

서울 안에서도 주요 생활 거점까지 이동시간이 오래 걸릴 수 있고, 반대로 경기도 일부 지역은 더 가까울 수 있다.

회사 이전이나 이직 등으로 주요 생활 거점이 변경될 가능성도 있으므로 특정 지역이나 직장을 고정된 기준으로 판단하지 않는다.

집알림은 이 과정을 대신 정리하여 사용자가 **지원할 가치가 있는 공고와 주택부터 빠르게 확인**할 수 있도록 한다.

## 핵심 흐름

```
새 공고 발견
↓
공고 내용 분석
↓
내 지원 가능 여부 확인
↓
공급주택 확인
↓
생활권 및 출퇴근 가능 여부 확인
↓
내가 관심 있는 주택 정리
↓
우선순위 알림
↓
지원 및 결과 기록
↓
다음 공고 반복
```

## 제품 원칙

- 서울 지역을 기본 대상으로 하되 행정구역보다 실제 생활 가능성을 함께 고려한다.
- 공고 자체보다 실제로 지원할 주택을 찾는 데 집중한다.
- 지원 가능 여부와 내가 살고 싶은지는 별도로 판단한다.
- 현재 직장 등 주요 생활 거점과 출퇴근 기준은 변경할 수 있어야 한다.
- 불확실한 내용을 임의로 확정하지 않고 공식 원문을 확인할 수 있게 한다.
- 최종 청약 신청은 사용자가 직접 수행한다.
- 기능을 많이 만드는 것보다 공고 확인과 지원 판단에 드는 시간을 줄이는 것을 우선한다.

## 성공 기준

새로운 공고가 올라왔을 때 사용자가 짧은 시간 안에 다음 내용을 확인할 수 있어야 한다.

1. 내가 지원할 수 있는 공고인가
2. 실제 공급되는 주택은 무엇인가
3. 내가 살고 싶은 주택이 있는가
4. 현재 생활 거점에서 현실적으로 출퇴근 가능한가
5. 과거 비슷한 모집의 경쟁률은 어느 정도였는가
6. 여러 후보 중 무엇을 우선 확인해야 하는가
7. 언제까지 지원해야 하는가
8. 과거에 비슷한 공고에 어떻게 지원했고 결과가 어떠했는가

공고문과 첨부파일을 매번 처음부터 분석하지 않고도 **지원할 가치가 있는 공고와 주택을 빠르게 결정하고, 당첨될 때까지 반복 지원할 수 있는 상태**를 목표로 한다.

## 운영 범위

제품 목표와 별개로 이 도구를 어떻게 운영할지에 대한 결정이다. 기능 설계의 전제이므로 함께 기록한다.

| 항목 | 결정 | 근거 |
| --- | --- | --- |
| 사용 인원 | 1인 개인 도구 | 멀티유저·로그인·권한·개인정보 처리방침을 만들지 않는다 |
| 실행 위치 | 로컬 맥 (현재 배포하지 않음) | 무료로 하루 2회 동기화를 돌릴 수 있는 유일한 구성이다. 배포로 옮길 수 있도록 로직은 실행 경로와 분리한다 |
| 런타임 | Node + Next.js | Supabase·PDF 파싱과 마찰이 없다 |
| 저장소 | **Supabase Postgres (Free)** | 배포로 옮길 때 저장소를 다시 만들지 않는다. 행 단위 과금이 없어 재고 5만 행을 그대로 둘 수 있다 |
| 알림 채널 | 텔레그램 발송 전용 | 나가는 요청만 있으므로 공개 URL이 필요 없다 |
| 알림 링크 | 공식 LH·SH 페이지 | 폰에서 `localhost`는 열리지 않는다. 최종 목적지도 공식 페이지다 |
| 판정 성향 | 정확도보다 누락 방지 | 동시 대상 공고가 10건 미만이다. 애매하면 남기고 원문 확인을 붙인다 |
| 신청 자동화 | 제출 직전까지만 | 인증수단을 대리 보유하지 않는다. 최종 제출은 사용자가 누른다 |

### 개인정보를 외부 DB에 두는 결정 (2026-08-20)

이 도구는 생년월일·소득·자산·세대 정보를 저장한다. 처음에는 로컬 파일 DB에만 두기로 했으나 **Supabase Postgres로 옮긴다.**

- 근거: 배포를 전제하면 저장소를 두 번 만들지 않는 것이 싸다. 무료 티어로 충분하고(500MB 중 재고 5만 행이 10% 이하), 행 단위 과금이 없다
- 대가: 개인정보가 내 컴퓨터를 떠난다. 그래서 **접속 문자열은 서버에서만 읽고, Supabase Data API는 사용하지 않으며, RLS를 켠 상태로 둔다**
- 감수하는 제약: 무료 티어는 **백업이 없고 1주 방치 시 프로젝트가 일시정지**된다. 그래서 내보내기 기능을 Phase 2에 포함한다

상세 기준은 `REQUIREMENTS.md` 16절에 있다.

## 기존 서비스 조사 (2026-08-20)

같은 문제를 다루는 서비스들이 어디까지 하는지 확인했다.

| 서비스 | 커버 | 개인화 기준 | 주택 단위 정보 | 자격 판정 | 경쟁률 |
| --- | --- | --- | --- | --- | --- |
| SH 청약알리미 (공식) | SH | 없음 (전체 발송) | 없음 | 없음 | 없음 |
| 마이홈 포털 (공식) | LH·지방공사 | 관심공고 등록 | API 수준 | 없음 | 없음 |
| 공공주택알리미 (웹·앱) | LH·SH·GH·HUG | 지역·기관 | 없음 | 없음 | 없음 |
| LH임대알리미 (앱) | LH·SH | 지역·유형 | 없음 | 없음 | 없음 |
| 알고 (앱) | LH·SH·행복주택 등 | 지역 | 불명 | 없음 | 없음 |
| 개인 정리 사이트 | 유형별 | 지역·면적·보증금 | **있음** (사람이 PDF에서 옮김) | 없음 | 없음 |

### 시사점

1. **모두 `지역 + 유형` 필터에서 멈춘다.** 자격 판정을 하는 서비스가 하나도 없다. 게으름이 아니라 데이터 벽이다 — 소득·자산·순위 조건은 어떤 공식 API에도 없고 공고문 PDF에만 있다(`SPEC.md` 5절).
2. **주택 단위 정보를 가진 곳은 사람이 PDF를 옮긴 곳뿐이고, 그래서 주소를 가리고 회원을 받는다.** 자동 수집으로 얻은 데이터가 아니라는 신호다.
3. **전국을 덮으려다 깊이를 잃는다.** 이 프로젝트는 1인·서울 생활권으로 범위가 좁으므로 깊이(주택 단위 분석·출퇴근·경쟁률 이력·지원 이력)로 가는 것이 맞다. 제품 원칙과 같은 방향이다.

### 참고할 것

- **캘린더 뷰** — 마감일 관리에 실효적이다. 지원 준비 단계에서 D-day와 함께 검토한다.
- **알림 발송 기준** — SH 공식 알리미는 `공고 후 접수일 이내` 발송이다. 우리 완료 조건(스케줄 실행 기준 12시간 이내)이 더 엄격하다.
- **공식 알리미를 안전망으로 병행한다** — 우리 수집이 실패해도 공고 자체는 놓치지 않는다.
- 앱 리뷰의 불만은 대부분 `알림 설정이 저장되지 않음`, `로그인 유지 실패`다. 로그인이 없고 프로필을 로컬에 저장하는 구조가 이 문제를 애초에 만들지 않는다.
